# 凡修录单文件基线

本文件记录 Vue 组件化迁移的冻结基线。旧版游戏未被改写，当前由 Vue 兼容桥加载。

- 基线文件：`legacy/fanxiulu-monolith.html`
- 基线行数：39,468
- SHA-256：`113F9ED589375E746C50A13EC6FE29B32BC6F255B208B7FACE43D7218A2685CC`
- 迁移阶段：非 UI 核心与服务边界抽离（旧版仍是默认运行时）
- 玩法改动：无
- 存档字段改动：无
- 云端接口改动：无

原始 EmberQuest 文件未随当前工作区提供，因此未创建伪造的 `emberquest-original.html`。

后续迁移应从静态数据、存档、战斗和挂机模块依次提取，并用固定随机种子与本基线回归对比。

执行 `npm run verify` 可检查入口行数、Vue 入口、冻结文件校验值和生产构建产物。

## 安全网阶段

- 使用 Vitest 保护冻结基线、关键存档约束和固定随机数实现。
- 使用 Playwright 检查桌面端与移动端登录页，以及本地进入角色道册主路径。
- 使用 `tests/fixtures/saves` 集中管理脱敏存档夹具。
- 使用 GitHub Actions 执行 `npm run verify:full`。

固定随机数已经接入新 `game-core` 的基础单人战斗、装备掉落和普通区域离线模拟；冻结旧版运行时仍使用原有随机源，正式接管前需要继续做同输入回归。

## 存档边界阶段

- `src/game-core/save` 负责旧版 24 槽解析、导入载荷识别、健康戳和 FNV-1a 哈希，且不依赖 DOM、Vue、Pinia 或云 SDK。
- `src/repositories/save.repository.ts` 定义存档仓储接口，`src/services/local/local-save.repository.ts` 提供浏览器键值存储实现。
- 当前覆盖本地槽位、健康戳、损坏 JSON 原文保留、最多 5 个版本备份、导入合并，以及纯 JSON、`EQSAVE1`、`EQSAVE2`、`EQSAVE3` 编解码。
- `EQSAVE2` 的 AES-GCM 密钥继续绑定导出时的来源和 User-Agent；`EQSAVE3` 继续使用 PBKDF2-SHA256 与 250,000 次迭代，可凭密码跨来源导入。
- `EQSAVE1` 保留旧版异或/Base64 行为及其无法编码非 Latin-1 文本的限制，只用于兼容缺少 Web Crypto 的旧环境。
- 当前旧版导出流程没有压缩步骤，因此本阶段没有引入虚构的压缩格式。
- 导入层负责结构校验、24 槽补齐和合并；装备、符文、功法、区域、队伍、LFG、佣兵血池与装备字段已通过纯迁移器清洗，不依赖旧版 DOM 全局状态。
- 新层会把非法基础类型或数组槽位记录为 `invalid-slot` 并归一化为空槽。旧版 `loadSlots()` 会原样保留此类值，因此在完成兼容评审前不会接管旧版运行时读写。
- `fanxiulu-native-save` 已升级为 v2：信封中的角色灵根与传承使用中文领域 ID，并记录独立原生 schema、旧档来源哈希和完整载荷哈希；影子门禁对比前会导出为旧英文 ID，因此不改变 `EmberQuest_slots`。
- `/?native=1` 已接入只读影子门禁：损坏旧档、无效/被篡改信封、来源过期或任意未忽略字段差异都会回退旧版。门禁不持久化候选信封，也不写回 `EmberQuest_slots`。
- 旧版游戏仍由兼容桥完整运行；本阶段未修改存档字段、槽位数量、玩法数值或云端接口。

## 非 UI 门禁

- 六槽装备穿脱、基础胜负结算、任务/掉落、普通/硬核死亡和逃跑判定已从 Pinia Store 移入纯核心。
- CloudBase P0 客户端仓储、服务端准备源码和 AI 立绘任务轮询已有可测试契约；真实 CloudBase/第三方环境仍未接入或部署，并按产品决定等待游戏机制定稿。
- 队伍、佣兵、宠物、怪物包、地下城离线和完整挂机目标已有纯核心主路径；冻结版仍负责正式玩家流程，新运行时在完整事件编排验收前不得提前接管。
- 装备强化链、背包容量、功法购买/记忆、状态持续伤害、武器触发、吸血、命名怪机制和存档字段级影子门禁已形成纯核心接口；玩法调整入口见根目录 `GAMEPLAY_CHANGE_GUIDE.md`。
- 原生挂机已恢复冻结版的功法槽 1→6 自动尝试顺序；关闭槽、空槽、冷却、法力不足和缺少目标都会被纯规划器跳过。原生战报同时保留中文消息与结构化事件，可导出、恢复并汇总回放，但不改变默认旧版显示。
- 冻结版 19 个 `BOSS_BY_ZONE` 配置已进入静态生成门禁；命名怪/首领的护盾吸收、40% 气血狂暴、毒液追加和每 3 回合护盾刷新按原顺序由纯回合编排器处理。区域首领生成、30 分钟冷却、保底区域装备和 18% 传说掉落已接入原生战斗边界。
- 原生离线恢复现在先按完整队伍人数计算每人修为份额，再把同额修为写入有效的本地组队角色槽；跨生死道、空槽和越界槽会被排除。冻结版离线结算不执行在线“分金”开关，因此灵石继续只进入当前角色。
- 详细完成度以根目录 `NON_UI_READINESS.md` 为准；其 P0 未完成项清零前不进入皮肤与交互设计。

## 中文显示层阶段

- 话术参考的权威术语按 `common`、`characters`、`skills`、`items`、`inventory`、`world`、`creation`、`combat`、`progression`、`dungeon`、`afk`、`casino`、`about`、`social`、`settings`、`interface`、`errors` 分类放入 `src/game-core/locales/zh-CN/`。新核心角色身份使用中文 ID；英文角色 ID 只保留在冻结数据和旧档兼容边界。
- `src/game-core/data/localization.zh-cn.ts` 保留历史兼容别名和参数化话术，权威词库优先级最高；`npm run lint:locale` 检查词表、内容名称与中文运行副本边界。
- 内容名称第二阶段集中在 `src/game-core/data/localization-content.zh-cn.ts`，覆盖区域、怪物、命名强敌、秘境、任务、材料、装备、随机词缀、套装、武器触发、功法、传承试炼、符纹和坊市丹药；生成数据和存档仍保存英文内部键。
- 原生实验入口通过 `translateLegacyText()` 使用该词表；默认 `/` 从冻结文件生成隔离的中文运行副本，并合并权威话术、历史兼容别名与完整内容名称。静态 HTML 和动态模板中的完整显示字面量在构建时直接替换；拼接式战报和状态说明先精确转换组成片段，再在实际写入边界按完整句式处理，动态角色/装备等内部 ID 不写回存档。
- 通用片段转换不处理 `the`、`for`、`of`、`and` 等连接词，也不接受带首尾空白的危险短键；多义词使用明确静态上下文，例如角色容量的 `Slots` 为“道册位”、赌场项目的 `Slots` 为“灵轮机”。该约束用于防止中英文词序拼接、点击换词与重复翻译。
- `src/game-core/domain/character-identity.ts` 是新玩法读取灵根与传承的唯一正式入口；`native-character-identity.adapter.ts` 负责旧英文存档与中文领域状态之间的双向转换。冻结生成文件不得手改。
- 运行副本删除冻结页原有的整页 `MutationObserver`、80/500/1800ms 延时扫描、父页面点击后补翻译以及 `Node`、`Element`、`Document` 的全局原型拦截。父 iframe 只注入小屏登录滚动保护，不读取或改写文字。
- 5 条公告的桌面/移动回归会实际点击本地入口并确认角色库激活；既有角色夹具回归会长等待后进入主游戏、推进教程并确认背包面板，同时比较点击前后的职业和六维文本。隐藏面板回归覆盖设置折叠、功法、队伍、秘境、赌场、坊市、区域、坊市服务、重修/飞升与完整悟道面板，并会实际生成妖物和攻击以检查动态战报；高等级丹医夹具会验证专精选择、无尽悟道、全部分支、推演、预设与方案对比的可见文本不含连续英文字符。
- 玩法定稿前等级仍显示为“修为等级 N”，不把数字等级擅自映射到具体境界；CloudBase 仍按产品决定延期。
